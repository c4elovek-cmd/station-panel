# Собственный плеер панели — panel-player

Новая реализация для `station-panel`, написанная с нуля на C11. Исходники, бинарник, схемы конфигурации, сборка и обновление не используют репозиторий `rodyatotu/soundya`. Название папки `soundya-ng` временно обозначает заменяемый компонент; исполнительный файл называется `panel-player`.

## Границы независимости

Собственные: управление очередью и процессами, HTTP-сервер, JSON-парсер, SoundCloud REST-клиент, HLS-парсер/демультиплексор, хранение двух аккаунтов, контроль позиции PCM.

Системные инструменты: `curl` для TLS/прокси, `mpg123` для MPEG Audio, `faad` для AAC, `aplay` для ALSA. Это независимые декодеры и транспорт, а не код исходного плеера. Их лицензии действуют отдельно. Сервис SoundCloud и работоспособность его токенов остаются внешними условиями — обойти их собственным кодом невозможно.

## Сборка

На Windows используется Zig 0.14.1 как C-кросс-компилятор (сам код демона — C, не Zig):

```powershell
pwsh -NoProfile -WindowStyle Hidden -File .\deploy\soundya-ng\build.ps1
```

Результат: `deploy/soundya-ng/build/panel-player`, статический `aarch64-linux-musl`. Zig не нужен на колонке. Компилятор и его кэши находятся на G:, дочерние процессы сборки скрытые.

## Запуск

По умолчанию сервис слушает **только `127.0.0.1:8765`**. Доступ из интернета — исключительно через авторизованную панель и существующий туннель. Публиковать порт напрямую нельзя: это внутренний доверенный API.

Переменные окружения:

| Переменная | Значение по умолчанию |
|---|---|
| `PANEL_PLAYER_DIR` | `/data/opt/panel-player` |
| `PANEL_PLAYER_PORT` | `8765` |
| `PANEL_PLAYER_HOST` | `127.0.0.1` |
| `PANEL_PLAYER_DEVICE` | `default` |
| `PANEL_CURL` | `/data/opt/entware/bin/curl` |
| `PANEL_MPG123` | `/data/opt/entware/bin/mpg123` |
| `PANEL_FAAD` | `/data/opt/entware/bin/faad` |
| `PANEL_APLAY` | `/usr/bin/aplay` |
| `PANEL_ALLOWED_ORIGIN` | пусто: POST с Origin запрещён |

Папка состояния должна существовать. Одновременно запускается один экземпляр: `flock` снимается ядром после завершения процесса. В `panel-player.json` хранятся токены, proxy, client_id, устройство, громкость и активный аккаунт; права новых файлов — `0600`. Запись через отдельный файл, fsync, rename и fsync директории. В API токены не возвращаются.

`PANEL_IMPORT_LEGACY=1` разрешает однократное чтение файлов старого плеера из той же папки. Это миграция **данных**, не зависимость от старого исполняемого файла. `config.json` при миграции не меняется.

## API

- `GET /health` — имя собственного backend и версия.
- `GET /api/status` — состояние, реальная PCM-позиция, очередь, аккаунты без секретов.
- `POST /api/cmd` — команда в текстовом теле; ответ `OK…` либо `error: …`.
- `POST /api/settings` — JSON-патч `token`, `sc_refresh`, `proxy`, `client_id`, `volume`, `account`.

Команды: `play <запрос/URL>`, `pause`, `resume`, `toggle`, `stop`, `next`, `prev`, `index <N>`, `seek <секунды или ±секунды>`, `shuffle [on|off]`, `repeat [on|off]`, `likes`, `recs`, `similar`, `playlist <URL/запрос>`, `account me|other [likes|recs]`, `queue`, `status`, `json`.

Загрузка очереди асинхронная: ответ `OK queued` означает **принятую задачу, а не начавшееся звучание**. `state=playing` появляется только после передачи настоящего PCM на устройство. Ошибки сети/токенов доступны в статусе. Во время сетевого запроса остаются доступными пауза, стоп, позиция и другие короткие команды. Стоп также отменяет незавершённую загрузку.

Обновление из чужого GitHub-репозитория намеренно отсутствует. AirPlay, управление телевизорами, Telegram, световое кольцо и прочие функции оригинального проекта не включены в эту реализацию. Будильники, PIN и like/unlike ещё не реализованы: API возвращает явную ошибку, а не фиктивный успех.

## Аудио и голос

Аудиопроцессы изолированы в собственной группе; стоп снимает всю группу вместе с curl и декодером. Сегменты и временные данные идут только в `/tmp`, а не на флеш колонки. Позиция считается по реально переданному PCM, пауза останавливает группу процессов.

Новый демон **не создаёт TCP-подключений к IPC `9875` и не перезапускает maind/platformd**. Голая «пауза» остаётся задачей уже установленного `deploy/soundya/fast_pause_watch.sh`, вызывающего совместимый `/api/cmd`. Расширенные голосовые фразы требуют отдельного подключения к уже существующему слушателю панели: старого распознавателя в новом демоне нет.

## Проверки

- `tests/test_json.c` — строгий JSON и Unicode.
- `tests/test_hls.c` — плейлисты/медиаконтейнеры на синтетических данных.
- `tests/test_http.py` — API отдельного тестового демона без SoundCloud и токенов.

```powershell
$env:PANEL_TEST_URL = 'http://127.0.0.1:18765'
python .\deploy\soundya-ng\tests\test_http.py
```

Не запускать проверки на рабочем порту: команды теста останавливают **тестовый** плеер. Живой прогон музыки и голосовой паузы — отдельный приёмочный тест.

## Статус внедрения

Код создаётся отдельно от действующей установки. Старый плеер пока не заменён. Переключение допустимо после сборки, тестов, сохранения локального бэкапа на G: и проверки медиапотока на колонке. Системные службы Алисы не входят в процедуру переключения.
