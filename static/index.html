Терминал

Сказать на колонке

Вход по SSH (порт 2222), пользователь root, пароль пустой. CLI yam в сборке демона нет — команды YAM дублируют HTTP API для удобства.

Подключение из обычного терминала (PowerShell / CMD / Linux)

Интернет-браузер не нужен — можно подключиться напрямую из консоли. IP колонки и порт берите в разделе «Система», ниже — примеры команд.

Windows — PowerShell или CMD

ssh -p 2222 root@192.168.0.172

Вход — без пароля (dropbear запущен с -B). Если попросит пароль — оставьте пустым и нажмите Enter. Выход из сессии: exit.

Linux / macOS / WSL

ssh -p 2222 root@192.168.0.172

Команда одной строкой (без интерактивной сессии)

ssh -p 2222 -o StrictHostKeyChecking=no -o BatchMode=yes root@192.168.0.172 "cat /proc/loadavg"

-o BatchMode=yes отключает интерактивные запросы — удобно для скриптов. Если подключаетесь впервые, опция -o StrictHostKeyChecking=no пропустит предупреждение о неизвестном хосте.

Копирование файлов (scp)

scp -P 2222 root@192.168.0.172:/tmp/file.txt .
scp -P 2222 file.txt root@192.168.0.172:/tmp/

Обратите внимание: у scp порт задаётся заглавным -P, а у ssh — строчным -p. Настоящий SFTP-подсистемы у dropbear обычно нет, поэтому sftp может не работать — используйте scp.

Слова активации

аудио ?
Зачем это и как связано с «Голосовыми командами»

Этот раздел — плагин wakeword. Он обучает станцию узнавать ваше слово-активацию (как «Алиса», но своё) и будить по нему. Это только «слушатель»: он ничего не делает и не произносит, лишь просыпается, когда услышит слово.

Связка целиком: слово активации будит станцию → она начинает слушать команду → плагин «Голосовые команды» ищет в речи триггер («дипсик») и отправляет его на ваш мост. То есть здесь — чем разбудить, там — что делать после.

Система и настройки

Мастер настройки

Одна кнопка проходит весь путь новой колонки: найти её в сети → проверить связь и часы → громкость → голосовой мост → слово активации → телеметрия. Шаги появляются по мере выполнения, ошибки не прерывают прогон. Обычно занимает до полутора минут.

Инструкция: что делает каждый шаг и что делать после

Шаги мастера:

  • Связь — сканирует сеть, находит колонку, подбирает порты YAM/SSH и ставит SSH-ключ панели (то же, что «Автонастройка»).
  • Станция на связи — демон YAM отвечает, модель опознана.
  • LED-часы — отправляет текущее время и яркость на кольцо. Закреплять не нужно: без закрепления колонка сама показывает реальное время.
  • громкость — читает общий регулятор ALSA (в «Обзоре» есть ползунок).
  • Голосовой мост — запускает локальный мост на ПК и проверяет LLM-токен: без него триггер сработает, но музыку подобрать нечем.
  • Слово активации — проверяет, записано ли хотя бы одно своё слово (раздел «Слова активации»).
  • Телеметрия — просто показывает состояние; отключается отдельной кнопкой ниже.

Если шаг помечен ✗: колонка и ПК должны быть в одной сети; SSH — порт 2222, пользователь root, пароль пустой; колонка должна быть залогинена в аккаунт Яндекса.

После мастера: «Подсветка» — часы и LED, «Слова активации» — запись своего слова, «Голосовые команды» — фразы-триггеры, «Обзор» — громкость и быстрые команды.

Голосовые команды

Как это работает и почему колонка может молчать

Этот раздел — плагин station-voice. Он делает одно: слушает распознанную речь, ищет в ней слово-триггер (например «дипсик») и, если нашёл, отправляет остаток фразы на ваш внешний мост (сервер по адресу выше). Сама колонка при этом ничего не произносит — обратная речь в плагине пока не реализована.

Порядок активации:

  1. Разбудить колонку — словом «Алиса» или своим словом активации.
  2. Сказать команду, которая начинается с триггера: «дипсик, включи музыку».

Если колонка молчит, проверьте:

  • Заполнен ли адрес моста и токен (без моста триггер срабатывает, но отправлять некуда).
  • Совпадает ли триггер со сказанным словом (по умолчанию — «дипсик»).
  • Что вы сначала активировали колонку, иначе речь не распознаётся.

Пароль панели

Телеметрия Яндекса

По умолчанию колонка отправляет Яндексу телеметрию: логи падений и диагностику. Панель убирает две autostart-службы — telemetry и fluent-bitd — из servicesList в quasar.cfg. Исходник конфига сохраняется рядом бэкапом, повторное включение возвращает его байт-в-байт.

состояние ещё не проверялось

Честно: применяется после перезагрузки колонки; на работу Алисы и обновления не влияет, но Яндекс при обновлении прошивки может перезаписать конфиг — тогда просто повторите отключение.

Питание колонки

Перезагрузка выполняется по SSH, связь оборвётся примерно через 2 секунды.
